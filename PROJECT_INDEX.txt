ARCHITECTURE OVERVIEW:
======================

Backend Flow:
  Frontend Request → Route → Controller → Service → Repository/Model → Database
  Database Change → Event → Service → Model Update → Response → Frontend

Frontend Flow:
  User Action → Component → API Service → Store/Hook → Re-render

Data Flow on Grade/Violation Change:
  1. Create/Update/Delete in Controller
  2. Service layer handles business logic
  3. Service calls ScoringService
  4. ScoringService recalculates all scores
  5. Scores persisted to database
  6. Response sent to frontend
  7. Frontend updates UI

KEY FEATURES:
=============

1. Automated Risk Scoring:
   - Academic: 60% weight based on recent grades
   - Behavioral: 40% weight based on violations
   - Auto-triggers on every grade/violation change

2. Role-Based Access:
   - Admin: Full access
   - Teacher: View students
   - Homeroom Teacher: Manage own class

3. Real-Time Statistics:
   - Student count
   - Risk distribution
   - Average scores
   - Class analytics

4. Responsive Design:
   - Mobile-friendly UI
   - Tailwind CSS styling
   - Touch-optimized navigation

5. Error Handling:
   - Validation on all inputs
   - Meaningful error messages
   - Exception handling
   - 404/401/422 responses
