PROJECT STRUCTURE: ISMS-EWA

BACKEND (Laravel):
app/
  Models/
    - Student.php (relationships with grades, violations, riskScore)
    - Grade.php (belongs to Student, triggers events)
    - Violation.php (belongs to Student, triggers events)
    - RiskScore.php (risk calculation storage)
    - SchoolClass.php (has many students)
    - User.php (auth users)
  
  Services/
    - ScoringService.php (core risk calculation engine)
      * calculateRiskScore() - main calculation
      * calculateAcademicScore() - maps grades to risk
      * calculateBehavioralScore() - maps violations to risk
      * determineRiskLevel() - low/medium/high classification
      * updateStudentRiskScore() - persists scores
    
    - StudentService.php (student business logic)
    - GradeService.php (grade management + automatic score updates)
    - ViolationService.php (violation management + automatic score updates)
  
  Http/Controllers/
    - StudentController (RESTful endpoints for students)
    - GradeController (nested routes for grades)
    - ViolationController (nested routes for violations)
    - SchoolClassController (class management)
    - AuthController (login/register/logout)
  
  Events/
    - GradeCreated, GradeUpdated
    - ViolationCreated, ViolationUpdated
  
  Repositories/
    - StudentRepository (data access layer)
  
  Http/Middleware/
    - Authenticate (Sanctum auth)
    - CORS handling
  
  Exceptions/
    - StudentNotFoundException
    - InvalidScoreException

database/
  migrations/
    - users, school_classes, students
    - grades, violations, risk_scores
  seeders/
    - DatabaseSeeder (sample data)

routes/
  - api.php (all API endpoints)

FRONTEND (React + Vite):
src/
  pages/
    - LoginPage.jsx (auth entry point)
    - DashboardPage.jsx (main student list with statistics)
    - StudentDetailPage.jsx (individual student view with grades/violations)
    - ClassesPage.jsx (class management)
    - AddStudentPage.jsx (create student form)
  
  components/
    - RiskComponents.jsx (RiskBadge, RiskScoreCard)
    - DashboardStatistics.jsx (statistics cards)
    - Layout.jsx (header and layout wrapper)
    - FormComponents.jsx (reusable form elements)
  
  services/
    - api.js (axios instance with interceptors)
    - apiService.js (all API calls)
    - dashboardService.js (statistics aggregation)
  
  hooks/
    - useAuth.js (auth state management)
    - useFetch.js (generic fetch hook)
  
  utils/
    - helpers.js (formatting, color mapping)

KEY FEATURES IMPLEMENTED:

1. SCORING ENGINE (ScoringService):
   - Academic score: based on latest 5 grades
   - Behavioral score: based on violation severity
   - Weighted calculation (60% academic, 40% behavioral)
   - Risk levels: low (0-20), medium (21-50), high (51-100)

2. AUTOMATIC RISK UPDATES:
   - Every grade create/update/delete triggers recalculation
   - Every violation create/update/delete triggers recalculation
   - Uses service layer for consistency

3. AUTHENTICATION:
   - Laravel Sanctum tokens
   - Login/register endpoints
   - Protected API routes

4. RESPONSIVE UI:
   - Tailwind CSS styling
   - Mobile-friendly design
   - Real-time statistics
   - Student filtering by risk level

API ENDPOINTS:
POST   /api/register                          Register user
POST   /api/login                             Login
POST   /api/logout                            Logout (protected)
GET    /api/me                                Current user (protected)

GET    /api/students                          List all students
GET    /api/students/:id                      Get student details
POST   /api/students                          Create student
PUT    /api/students/:id                      Update student
DELETE /api/students/:id                      Delete student
GET    /api/students/risk-level?level=high   Filter by risk level

GET    /api/classes                           List all classes
POST   /api/classes                           Create class
GET    /api/classes/:id                       Get class details
PUT    /api/classes/:id                       Update class
DELETE /api/classes/:id                       Delete class

GET    /api/students/:id/grades               Get student grades
POST   /api/students/:id/grades               Add grade (triggers score update)
PUT    /api/students/:id/grades/:gradeId     Update grade (triggers score update)
DELETE /api/students/:id/grades/:gradeId     Delete grade (triggers score update)

GET    /api/students/:id/violations           Get student violations
POST   /api/students/:id/violations           Add violation (triggers score update)
PUT    /api/students/:id/violations/:violId  Update violation (triggers score update)
DELETE /api/students/:id/violations/:violId  Delete violation (triggers score update)

DATABASE SCHEMA:
- users: id, name, email, password, role, timestamps
- school_classes: id, name, grade_level, homeroom_teacher_id, timestamps
- students: id, name, email, student_id, class_id, risk_score, timestamps
- grades: id, student_id, subject, score, semester, academic_year, timestamps
- violations: id, student_id, description, severity, reported_by, reported_date, timestamps
- risk_scores: id, student_id, total_score, academic_score, behavioral_score, risk_level, last_updated, timestamps
- personal_access_tokens: for Sanctum auth

ARCHITECTURE PATTERNS:
- Service Layer: All business logic in services
- Controller as Router: Controllers delegate to services
- Dependency Injection: Services injected into controllers
- Event-Driven: Automatic updates on data changes
- Repository Pattern: Data access abstraction
- Custom Exceptions: Meaningful error handling
